# 输入注入：真机验证清单（UNVERIFIED 项）

本文件列出**只能在真实 Windows 桌面/真机环境验证**的项目。截至批 11（`63e3cc6` 之后），
以下内容均已通过单元/集成测试与变异反证，但**未在真实桌面实跑**。

> 与批 4/5 时代的差异（新增待验面）：单会话租约 `max_input_sessions=1`（默认）、
> held-release 队列豁免、限流 400/1000 平台动作每秒、`InputStats` 周期/终值打印。
> 这些只在**真实输入压力**下才会暴露，务必按第 8-10 节执行。

> 注：任何一项实跑都会**真实移动本机键鼠/前台窗口**。请在专用测试机或可接受干扰的环境执行，
> 并确保 `--allow-input` 只在明确知情时开启。

## 0. 前置
- [ ] 用 `rtsc_server_host --allow-input`（默认凭据校验在）启动；确认启动行打印 `input=on`。
- [ ] 用 mstsc 连上，确认画面之外**输入能落到服务器桌面**（本批的核心缺口）。

## 1. 键盘
- [ ] 普通字符（A/B/1）落到**当前前台窗口**。
- [ ] 扩展键：方向键、Home/End、Delete、右 Ctrl/右 Alt、Win 键、Applications 键。
      期望：`KEYEVENTF_EXTENDEDKEY` 生效，`右 Win` 打开开始菜单。
- [ ] 组合键：`Ctrl+Shift+Esc` 打开任务管理器；`Alt+Tab` 切换窗口；`Ctrl+Alt+Del` **预期无效**
      （SendInput 无法合成 SAS；需 `SendSAS` + 服务/策略，v1 未实现）——记录实际表现。
- [ ] Pause/Break 键：解码层忠实上送 `extended1`（0xE1 前缀），SendInput 只能表达 0xE0，
      因此**整条 PAUSE 序列（`04 1D`/`00 45`/`05 1D`/`01 45`）被整体丢弃、不注入**（批 16）。
      **验收要点：按 Pause 后本机 NumLock 指示灯/状态必须不变**——若发生翻转即回归。
      `[UNVERIFIED-真机]`
- [ ] 验证 PAUSE 抑制不误伤：先按 Pause，再单独按 NumLock 一次，NumLock **必须正常切换**
      （PAUSE 窗口最多吞一次 tap，不得永久吞掉 0x45）。`[UNVERIFIED-真机]`
- [ ] `kSync` 会终止 PAUSE 窗口（批 17）：Pause 后紧接状态同步，随后的 NumLock 仍应生效。`[UNVERIFIED-真机]`
- [ ] NumLock/CapsLock 状态同步（`kSync`）：v1 **不注入**，记录是否造成状态不一致。

## 2. 鼠标
- [ ] 绝对移动落点准确（含多显示器组合、DPI 缩放 125%/150%）。
- [ ] 左/右/中/侧键 1/侧键 2 身份正确（侧键在**相对模式**下也应正确，见 `kMouseRel` X1/X2 修复）。
- [ ] 按钮释放不残留按下状态（拖拽后松开，目标不应保持选中）。
- [ ] 滚轮方向：**与 mstsc 同向**（本地滚一格 = 对端滚一格）；3 格快滚应滚 3 格（切块修复）。
- [ ] 横向滚轮（HWHEEL）：对端支持时方向正确（右为正）。
- [ ] 快速滚动（>17 格/事件）会**丢弃超出量**并计入 `dropped_wheel_units_count()`——确认无异常卡顿。

## 3. UIPI / 完整性级别
- [ ] 以管理员身份运行 `rtsc_server_host`，对端可操作**管理员权限**的窗口（如以管理员运行的程序）。
- [ ] 以普通用户运行，对端操作管理员窗口应是**静默失败**（`SendInput` 返回条数 < 请求条数，
      无异常）——记录是否只表现为"没反应"。
- [ ] 确认服务器至少打印了注入失败计数/限流日志（5s 限流）。

## 4. 多会话（8 会话并发）
- [ ] 两个客户端同时连接并注入：确认**互相干扰**的表现（同一物理桌面）。
- [ ] 会话断开时 `ReleaseSession` 补发 keyup/按钮 up：断开后不应有键/按钮"卡住"。
- [ ] 一个会话在注入键时另一会话断开，确认无崩溃、无卡键。

## 5. 安全与隐私
- [ ] `--allow-input --no-enhanced` → **必须拒绝启动**（EXIT=2）——已实测。
- [ ] `--allow-input --allow-any-credentials` → **必须拒绝启动**（EXIT=2）——已实测。
- [ ] `--allow-input-unverified` 逃生门：确认打印显著警告 banner。
- [ ] 确认注入的输入**在本机会话可见**（光标自走、键落到前台窗口）——这是已知且无法隐藏的行为，
      确认文档/`--help` 已如实说明，并确认操作者知情。

## 6. 慢路径输入（P-10）
- [ ] 若真实 mstsc 在未广告 `0x0020`/`0x0008` 时改发**慢路径**（`pduType2=0x1C`），
      确认慢路径解码路径也能注入（SCANCODE/UNICODE/MOUSE/MOUSEX/MOUSEREL）。
- [ ] 记录 mstsc 实际走的是快路径还是慢路径（需抓包或日志）——**这是判断 P-9 修复是否生效的关键**。

## 7. 已知不注入（设计决定，非缺陷）
- `kMouseRel`（v1 不注入，因相对移动受鼠标加速 1~4 倍污染）
- `kSync`（v1 不注入）
- `Ctrl+Alt+Del`（需 SendSAS，v1 不实现）

## 8. 单会话租约（`max_input_sessions`）
- [ ] 用默认 `--max-input-sessions 1` 启动；第一个产生**可注入**事件的客户端取得租约，
      第二个客户端的按键应被**拒绝**且启动行/日志出现 `input lease denied summary`（计数递增）。
- [ ] 只发 `kSync`（NumLock 状态同步）的客户端**不应**占住租约——记录第二客户端是否仍能操作。
- [ ] 第一个客户端断开后，第二个客户端**下一次可注入事件**应获取租约（无需重连）；
      确认没有"必须先动一下才生效"以外的额外等待。
- [ ] `--max-input-sessions 2` 时两客户端都能注入，且**互相干扰**（同一物理桌面）——记录实际表现。

## 9. 限流与队列（真实压力）
- [ ] 按住某键自动连发（或脚本高频按键）触发限流后，`input stats` 行应出现
      `input_rate_limited` 递增，而**本地键不会卡住**（held-release 仍豁免）。
- [ ] 长时间拖拽并快速画圈（高频移动）：`input_dropped_queue` 可能递增，画面应无卡死/崩溃。
- [ ] 客户端**异常断开**（拔网线/杀进程）时按住的键/按钮必须被 `ReleaseSession` 补发 up：
      本地桌面不得残留"按住"状态。这是 held-release 与合成 up 的关键真机验证点。
- [ ] 断开后继续用另一客户端注入，确认无残留移动/按键，日志无 `sessions_` 相关异常。

## 10. 可观测（`input stats`）
- [ ] `--once` 与 `--seconds N` 正常退出时打印 `input stats (final)`，六个计数与实际观察一致
      （注入成功应有 `input_injected` > 0）。
- [ ] 无界模式（不带 `--seconds`）按 Ctrl+C **不会**打印 final（当前无 SIGINT 处理）——
      确认文档未承诺该行为。
- [ ] 周期性 `input stats (periodic)` 只在计数变化时出现，**不得刷屏**；`lease denied summary`
      不应与首次 WARNING 重复刷同一条。
- [ ] UIPI 静默失败场景下，`input_send_failures` 应增长（用于区分"没反应"与"没送到"）。
- [ ] 异常断开（拔网线/杀进程）后 `input_release_failures` 应保持 0（补发 up 成功）；
      若增长说明合成 up 入队失败，本地可能残留按住状态——与 §9 的"不得残留"互为对照。
- [ ] `input_worker_failures` 应恒为 0（worker 线程未吞异常）；非 0 表示有注入动作被静默丢弃。

## 11. 停止与退出（`Stop()` 契约）
- [ ] 正常关闭（`--seconds` 到期）必须在**有限时间**内返回；若日志出现
      `stop: N session(s) still live after Xs`，说明某会话线程未退出（属缺陷，请记录 N 与场景）。
- [ ] 关闭后立即继续使用宿主对象（如销毁 clipboard/desktop source 并退出进程）**不得崩溃**：
      `Stop()` 契约是"返回时已无会话线程访问借用对象"。
- [ ] 客户端连接后不发送任何输入再关闭服务端：`Stop()` 应立即返回（无会话积压）。
