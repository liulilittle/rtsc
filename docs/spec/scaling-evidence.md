## 4. 对齐决策（父代理裁决）

1. **scale == 1.0** → 精确拷贝（保留 memcpy；居中 1:1 也应走精确路径）。
2. **scale > 1** → 最近邻（整数倍保留 k×k 专用内层循环以满足性能；非整数改为最近邻）。**与 mstsc 一致**。
3. **scale < 1** → **精确面积平均**（覆盖加权 + 半像素中心）。**有意改进**：GDI 用近似 box（实测偏差 ±4/255 量级），我们用精确 box。
4. **alpha** → 四通道同权重。**有意改进**：GDI 不处理 alpha。

### 有意偏离清单（必须在文档与代码注释中如实标注，禁止声称「与 mstsc 一致」）

| 编号 | 偏离项 | mstsc 行为 | 本项目 | 理由 |
|---|---|---|---|---|
| D-1 | 降采样精度 | 近似 box（±4/255 偏差） | 精确 box | 可手算、可测、无抖动 |
| D-2 | alpha 重采样 | 不处理 | 四通道同权 | Present 会把 alpha 写入 DIB，未来合成需要正确值 |
| D-3 | 1px 二维棋盘 2x | 压平为 128（不稳定，随尺寸翻转） | 保留块复制（0/255） | 复刻抖动伪影会毁掉文字/线条清晰度，且行为不可移植 |

## 5. 验收要求（先红后绿；期望值禁止取自生产输出）

期望值来源仅限：手算整数面积公式、独立参考实现（不得调用被测代码）、本文件 E7 实测值。

- 降采样（**单值，不接受区间或双值**）：0.5x 1px 条纹（**双轴**）→ `128`；0.5x alpha 硬边 → `0 128 255 255`；0.5x 白底 1px 黑线（奇数列）→ 该列 == `128`；0.8x ramp 5→4 → `10 71 133 194`；7x5→3x2 → `26 108 190`；1x8→1x3 → `28`。
  注：单轴缩放 GDI 给 127，但本仓 `ComputeViewTransform` 用同一 scale 算双轴，不会出现单轴降采样（见 E11）；实现统一 round-half-up，故单轴亦为 128，属**有意偏离 D-1**。
- 升采样：2x/3x 必须与独立 nearest 参考 `memcmp==0`（回归守卫，防止被"修"成模糊）；1.37x/1.33x 输出必须 ⊆ 源像素集合（不产生新颜色）。
- 1:1：`memcmp==0`（含居中 letterbox）。
- 边界：1x1→NxN 全等；1x200→1x333 单调；奇数尺寸无越界。
- 性能（Release，中位 ≥9 次）：1:1 <1ms、1:1 letterbox <0.6ms、2x <8ms、0.8x(1080p→1536x864) ≤22ms、0.5x(4K→1080p) ≤25ms、1.33x(1080p→2560x1440) ≤10ms。
- 变异反证：降采样改回抽点 → 降采样用例全红；升采样改回双线性 → nearest 守卫红。

### E9 降采样的舍入约定（GDI 与精确 box 的差异）

- GDI：`(0+255)/2 = 127.5` → 输出 **127**（截断）。
- 精确 box + 舍入 `(acc+den/2)/den` → **128**。
- 属**舍入约定差异**，非行为分歧。本项目采用**四舍五入**（更对称），在偏离清单中记为 D-1 的一部分；相应测试期望写 128（不接受 127/128 双值，避免测试变松）。

### E10 GDI HALFTONE 在**二维高频内容**上会产生源中不存在的新值（抖动）

审计甲实测（`probe_dither.exe`，自然纹理图）：

```
natural 1920x1080 -> 3840x1080 : mean|d|=0.6771 max|d|=35  not-in-source = 302940/4147200 (7.305%)
natural 1920x1080 -> 2400x1080 : mean|d|=0.7548 max|d|=42  not-in-source = 300240/2592000 (11.583%)
natural 640x480   -> 1280x480   : mean|d|=0.7473 max|d|=35  not-in-source =  44880/614400  (7.305%)
低频 ramp 1920->2400/2560/2880/3840 : mismatch=0  max|d|=0
```

→ **低频内容（渐变/条纹/台阶/1px 线）GDI = 纯最近邻（max|d|=0）；二维高频内容 HALFTONE 会抖动，7.3–11.6% 像素出现源中不存在的值。** 这与「1px 二维棋盘 2x → 128」同一机制。

**对验收的影响（重要）**：
- 升采样断言**只能**用 E8 公式推出的源索引作为黄金标准，且**只在低频内容上**验证；
- **不得**用 GDI 实际输出作为测试期望（否则会被抖动污染）；
- **不得**对二维高频内容（如 1px 棋盘）设断言——GDI 自身行为不稳定且我们有意不复刻；
- 措辞禁止写「与 GDI 逐字节一致」，只能写「相位与 E8 公式一致」。

### E11 降采样舍入：GDI 的 127/128 取决于**是否双轴缩放**

### E13 最终验收判据（三条正交，取代"⊆ 源集合"）

审计乙提出、父代理采纳。三条判据各自独立、互不替代：

**(A) 低频内容 → 必须逐像素等于 E8/C 式相位。**
内容限定：渐变、台阶、条纹、1px 竖线。P-G 实测 GDI 与 C 式在生产宽度（1920→2400/2560/2880/3840）`maxdiff=0`，故可作黄金标准。

**(B) 变异守卫 → `dst` 颜色集合 ⊆ `src` 颜色集合（新值占比必须为 0）。**
不依赖 GDI，适用于任意内容。nearest 恒为 0%；双线性/box 在非整数放大 > 0%。此判据同时反向证明"GDI 自身在高频内容会产生 1.71% 新值，故 GDI 不能作唯一黄金标准"。

**(C) 1px 二维棋盘 2x → 不设值断言，仅记偏离 D-3。**
乙方扫描 S=2..482（两轮一致）：`S≤46 → 128`、`S=50..122 → 0/255`、`S≥130 → 128`；甲方 ≤48/56..128/≥160。结论一致：确定性但随尺寸翻转，不可作契约。

### E16 混合轴情形 + round-half-up 必须是整数运算（非 double 倒数）

**混合轴**：`scale` 的 x/y 可能一个缩小一个放大（如 16x8 → 8x16）。契约补充：**任一轴缩小 → 取 kArea**（缩小轴做面积平均、放大轴在该方向上退化为 E8 单 tap 复制）。理由：对缩小轴做最近邻会丢像素，对放大轴做面积平均无意义（覆盖面积恒为 1）。

**round-half-up 的实现要求（审计丙 F1，父代理独立验算）**：

不得用 `acc * (1.0/total) + 0.5` —— `1/total` 在 double 中不精确且方向可能向下，精确平均恰为 `N+0.5` 时会得到 `N+0.4999999999999999`，加 0.5 后仍 < N+1，截断为 N。

```
total=1296000, weight=729000, value=56
  exact average            = 31.5
  double acc*(1/total)     = 31.499999999999996
  +0.5 then truncate       = 31        (契约要求 32)
  integer (acc + total/2)/total = 32   (正确)
```

实测影响：**1440x900 桌面 @ zoom 0.75（标准预设）→ 1080x675**，随机内容失配 **18948/2187000 = 0.866%**，全部偏 –1；1920x1080/1366x768/1280x1024 恰好为 0%（那些 total 的倒数方向安全）——**正是"只在特定缩放比才炸"的隐蔽缺陷**。

→ 必须用整数运算：`(acc + total/2) / total`（偶/奇 total 均等价 round-half-up）。快速路径同理 `(a0 + area/2) / area`。测试须包含一个**精确 .5 平局**的用例（如 zoom 0.75 的单点场景）。

### E17 0.4x（4K→1536x864）性能预算

审计甲/乙独立实测：`3840x2160 → 1536x864`（0.4x）**27.9–30.9 ms**。E15 原预算表只覆盖 0.5x/0.8x，缺此档。

原因：0.4x 是**非整数比**（2.5 倍），走通用 tap 路径；0.5x 是整数比走 uniform 快路径，故 0.4x 慢约 2 倍。要再快只能放弃精确覆盖加权，不建议。

→ **补入预算：`0.4x (4K→1536x864) ≤ 35 ms`**；并要求实现不得因后续优化（如整数除法改造）突破该值。
