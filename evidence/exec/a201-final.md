## 2. 为什么甲的判据不成立（决定性证据）

甲提出：

> 批 0 在旧 `:42` 前插入 2 行 ⇒ 对任意 `n>=42`：若 `backup[n] == current[n+2]`（字节级相同），
> 则该 n 是批 0 前的行号，引用未更新。

**这个判据对插入点之后的每一行都成立**，因为它测的是「这一行有没有位移」，而不是
「这条引用是否正确」。

实测：

```
n in [42,700): backup[n]==current[n+2] 成立 658/658 = 100.0%
```

**100% 成立 = 没有区分力。** 它无法区分：

- (a) 引用仍是旧值 `n` → 真的失效
- (b) 引用已改成新值 `n+2` → 正确

两种情况下把文档里的数字喂进去，判据都返回 True。

**我自己的 v1 扫描器沿用了同一判据，报出 86 处；其中 18 处是我已经修好的新值** ——
纯粹假阳性。

## 3. 为什么「加 2」也不成立

原文档 `doc:494` 写：

```
| `Shutdown()` 也会置 `closed_=true` | `src/net/tls_schannel.cpp:429` |
```

- `old:429` = `if (st == SEC_E_OK || SEC_I_CONTINUE_NEEDED) {`（**if 条件行**）
- `old:430` = `closed_ = true;`（**文档真正指的那一行**）

**原引用本身就差 1。** 机械 +2 得到 `:431`（仍是 if 条件行），我第一轮就是这么改的，
**引入了新的错误**：文档说「置 `closed_=true`」，引用却指向 `if` 条件。

正确值是 `:432`（`closed_ = true;` 在 Shutdown 内）。

## 4. 最终判据：语义匹配

对每处引用：
1. 从**周围散文**读出它指的是哪个构造（例如「置 `closed_=true`」→ `closed_ = true;`）；
2. 在**当前文件**里定位那个构造；
3. 写入找到的行号，**并把锚点文本写在旁边**。

这样：
- 行号是按语义找到的，不是算出来的；
- 锚点保证下次行号漂移时引用仍然可用。

- 语义匹配用「锚点首 token 出现在被引用行/区间内」判定。若某构造在区间内出现多次，
  无法区分「指第一个」还是「指第二个」。当前 57 处均唯一。

  只验证「引用指向的位置与文档声称的构造一致」。
