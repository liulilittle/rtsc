## 2. 关键判定：哪些引用必须修

不是所有引用都要修。必须区分三类：

| 类型 | 判据 | 处置 |
|---|---|---|
| **导航性**（「这里实现了 X，去改这里」） | 执行 AI 会按它定位 | **必须指向当前正确行** |
| **记录性**（「原来写 N，应为 M」「行号已 +2」） | 描述过去状态 | **必须保留旧值**，改了就没证据 |
| **越界/异文件** | 指向 audit-a.md 自身或已删代码 | 不动 |

**关键范围**：`final.md` §9 明确说交付给执行 AI 的是
`audit-a.md` **§19 执行交接包**（doc:3205-4230）。只有这一段是执行指令，
其余 5000+ 行是审计历史。**420 处裸引用绝大多数在审计历史里，属于记录性。**

## 6. 验证：红绿双证

### 6.1 第一版验证器失败（记录在案）

`verify_sec19.py` v1：只检查「行号 ≤ 文件行数」。
**红证：把 8 处旧值注回去，仍然报 0 MISMATCH、exit=0。**
→ 范围检查**零区分力**（memory 规则 55 的又一实例）。

### 6.2 第二版验证器也失败

v2：硬编码 `EXPECT = [(doc行, 文件, 行号, 构造)]`。
**红证：注入旧值后仍报 0。** 原因：**它根本没读文档**，只拿硬编码的行号去查源文件。
→ 这是「验证器测的是自己的常量，不是被测对象」。

### 6.3 第三版（最终）通过

v3：**从文档里读出引用号**，再断言「它指向的源行包含散文所说的构造」。

```
=== section 19 handoff package: semantic citation check ===
citations verified OK : 16
citations MISMATCH    : 0
exit=0
```

**红证**（注入 8 处旧值到副本，验证器指向副本）：

```
injected 8 regressions
--- RED (expect MISMATCH > 0, exit 1) ---
citations verified OK : 7
citations MISMATCH    : 9
  doc:4002  cited 409, 429 -> got 'return MakeError(Status::kOk, 0, "");'
  doc:4021  cited 178 -> got 'return MakeError(Status::kOk, 0, "");'
  doc:4030  cited 230 -> got 'Error Receive(const uint8_t* ciphertext, size_t size,'
  ...
exit=1

--- GREEN (real doc) ---
citations verified OK : 16
citations MISMATCH    : 0
exit=0
```

**红证 9 处 ≠ 注入 8 处**：因为 `doc:4002` 和 `doc:4123` 各有两个引用，
注入后每个都产生两条失败记录（主引用 + 第二引用）。

## 9. 局限（不隐瞒）

- 裸 `` `:NNN` `` **没有文件名，无法机器判定目标文件**。我的 v3 全量扫描器
  `verify_a201_v3.py` 用上下文启发式，产生 61 处误报（指向 `test_licensing.cpp`、
  audit-a.md 自身、已删代码）。**该脚本不能作为门禁**，只能作为人工复核辅助。
- `verify_sec19.py` 的 `EXPECT` 表是**人工维护**的。若文档新增引用而表未更新，
  验证器不会发现。这是覆盖缺口，必须靠「新增引用必须同时加表项」的纪律补。
- 未验证「§18 的 6 处是否还有更多同型」。§18 有 400+ 行分析表，
  逐条核实成本高。**当前判定：§18 属审计历史，行号错不影响执行。**
