## 4. 甲最关键的发现：红证 A 证明不了语义检查

我的红证 A：把文档里的 `:169` 改回 `:167`，验证器报错。
**甲指出这证明的不是我以为的东西**：

> 失败原因是 `anchor not found`，而 **anchor 文本里内嵌了 `:169` 本身**。
> A 只证明了「锚点匹配」有区分力，**没证明「构造检查」有区分力**。

**甲是对的。** 锚点 `'| **S10** | `:169` 恢复 `consumed = in_size` 且不吸收尾部'`
本身就含 `:169`，改回 `:167` 后锚点找不到 → 报 `anchor not found`，
根本没走到「源码第 169 行是否含该构造」这一步。

**甲做了红证 B**：文档一个字节不动，只把**源码** `:169` 改成
`consumed = in_size_other;`：

```
checks passed : 30   checks FAILED : 2
  [§6]  doc:725  cites :169 -> 'consumed = in_size_other;   // SEMANTIC RED'
  [§18] doc:3128 cites :169 -> 'consumed = in_size_other;   // SEMANTIC RED'
exit=1
```

**文档未改、只有源码变、仍然报错 → 语义检查独立生效。**

**这才是「语义判据」的真证明。** 我已把它固化为 `evidence/exec/semantic_redtest.py`。

→ **memory 规则 76**。

## 5. 甲对 R-3 的订正：我的理由不准确

我说「插 5 行会让硬编码章节边界失效」。**甲实测：**

| 变体 | 未改 | `doc:3207` 前插 5 行 |
|---|---|---|
| 动态 | exit=0 | **exit=0** |
| 硬编码 | exit=0 | **exit=0** |

**两者都过 → 我的具体断言是错的。** 原因：§19 的锚点离 §19 末尾都很远
（最小 90 行），插 5 行跨不过去。

**甲找到真正的最小反例**：全部 32 个锚点到章节末尾的**最小距离是 12 行**
（`doc:724` 在 §6，§6 止于 737）。在 §6 里 `doc:724` 前插 **14 行**：

```

hardcoded +14 lines in §6  -> exit=1  passed=30 failed=2
```

**正确表述**：「某个被检查的锚点**跨过**其冻结的章节边界时」硬编码失效，
不是「插 5 行」。

**甲的订正准确，我接受。** 动态边界的结论不变（确实更健壮），但理由必须改。

→ **memory 规则 77**。

## 9. 我这一轮的错误（三处，全部由甲发现）

1. **写「已由 X 验证」却没重跑 X** —— `verify_sec19.py` 已坏，文档仍引用它。
   **根因**：我修改了文档结构（插 5 行），却没意识到这会让以 doc 行号作 key
   的验证器失效。**「改 A 就要重跑依赖 A 的 B」是基本纪律。**
2. **「所有」超出能力** —— 覆盖 4.0% 却写「所有」。
3. **红证 A 证明不了语义检查** —— 锚点文本内嵌行号，导致红证只测了锚点查找。
   **根因**：我没意识到「红证的注入点」和「判据的作用点」必须是两个独立的东西。
